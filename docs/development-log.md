# Sabado 한국어 패치 제작 기록

## 현재 배포판: 0.1.5 — 자동 탐색 수정 및 사용 안내 정리

2026-11-04, 배치 파일을 실행하면 게임을 직접 찾아야 한다는 제보를 실제 사용자 계정에서 재현했다. HKCU의 Steam 경로는 `c:/program files (x86)/steam`, 기본 경로는 `C:\Program Files (x86)\Steam`이었고, `Select-Object -Unique`가 대소문자가 다른 두 경로를 구분했다. 동일 게임이 두 번 검색되어 `Count -eq 1` 조건을 통과하지 못하고 파일 선택 창이 열렸다.

탐색을 `installer/discovery.ps1`로 분리하고 경로 구분자 정규화와 대소문자를 무시하는 중복 제거를 적용했다. 유효한 설치본을 찾으면 자동으로 제시하고, 찾지 못하면 기존 파일 선택 창으로 넘어간다. 실제 설치본이 여러 개여도 첫 유효 경로를 제시하며 사용자가 확인 창에서 다른 위치를 선택할 수 있다. 없는 라이브러리는 건너뛰고 추가 Steam 라이브러리도 계속 검색한다.

- Windows PowerShell 5.1에서 경로 대소문자·구분자 중복, 추가 라이브러리의 한글/공백 경로와 다른 설치 폴더명, 삭제된 라이브러리, 복수 설치본, 게임 미설치, Steam 미설치 등 자동 탐색 시나리오 6개 통과.
- 실제 사용자 레지스트리와 Steam 라이브러리를 사용해 게임 폴더가 단일 문자열로 검색됨을 확인했다.
- 최종 ZIP 업데이트 시험 중 Windows `File.Replace`가 일시적으로 파일 교체를 거부하는 오류도 재현했다. 공유·잠금·교체 파일 제거 오류에 한해 최대 6회 재시도하고, 재시도 전에 대상 해시가 변하지 않았는지 검사한다. 오류에는 대상 파일 경로를 포함한다. 일시 실패와 지속 실패 시 복원 검사를 추가해 설치 검사 18개가 통과했다.
- 실제 게임 파일 복사본에서 새 배포판으로 업데이트·제거·재설치하고 원본 7개 해시가 유지됨을 확인했다. Python을 PATH에서 제외하고 Windows PowerShell 5.1로 실행했다.
- README와 0.1.4/0.1.5 릴리스 본문에서 구현 세부 사항과 테스트 수치 등을 덜어내고 일반 사용자용 다운로드·설치·제거 안내로 정리했다. 상세 구현·검증 정보는 개발 문서에 남긴다. 사용자 요청에 따라 두 릴리스의 별도 체크섬 첨부 파일을 제거하고, 이후 배포에서도 설치 ZIP만 첨부하도록 생성 코드와 개발자 안내를 정리했다.

## 이전 배포판: 0.1.4 — Python 없는 설치·제거

2026-11-04, 일반 사용자용 배포 ZIP과 `설치.bat`, `제거.bat`, `복구.bat`를 추가했다. Windows 기본 PowerShell 5.1을 사용하며 별도 Python·Unity Editor·Git 설치나 설치 중 다운로드가 필요하지 않다. Steam 기본/추가 라이브러리를 탐색하고 찾지 못하면 게임 실행 파일을 선택한다. 보호된 게임 폴더에서는 해당 작업에 필요한 관리자 권한으로 다시 연다.

설치·업데이트·제거 모두 작업 전 파일과 설치 기록을 백업하며, 실패 시 이전 상태로 복구한다. 전원 중단 등으로 남은 `SabadoKorean.pending.json`은 복구 배치 파일로 처리한다. 원본 게임 및 패치 파일 해시, 설치 경로, 관리 파일 허용 목록을 검사한다. 새 백업은 `%LOCALAPPDATA%\SabadoKorean\Backups`에 보관하고 기존 Python 설치 기록도 읽는다. 기존 원본 백업이 필요한 업데이트에서는 새 백업 위치로 복사한다.

확인 결과:

- Windows PowerShell **5.1.26100.9711**에서 설치·업데이트·제거·재설치, 한글/공백/괄호/앰퍼샌드 경로, 원본 설정 복원, 다른 모드 충돌, 변조·손상·경로 이탈 거부, 쓰기 실패 롤백, 중단 복구, 기존 Python 기록 이전, 게임 업데이트 후 제거 등 **16개 시나리오 통과**.
- 기존 Python 설치 검사 **12개**, C# 표시 변환 검사 **16개**, 번역·토큰·대상 원본 해시 검사 통과.
- 배포 ZIP을 한글 경로에 풀고, 실제 게임 원본 7개와 기존 0.1.3 관리 파일 29개를 복사한 테스트 설치본에서 **0.1.3 → 0.1.4 업데이트 → 제거 → 새 설치**를 실행했다. `PATH`에서 Python을 제외했고 Windows PowerShell만 호출했다. 검사한 실제 게임 원본 7개 SHA-256 변화 없음. 사용자 실게임 설치본은 이 테스트로 변경하지 않았다.
- 로컬 Steam 설치 경로 자동 탐색 확인. 별도 Python이 설치되지 않은 깨끗한 가상 머신, UAC 대화형 승인, 안내 창의 시각적 검수는 수행하지 못했다. 컴퓨터 사용 도구에 미리보기 창이 노출되지 않았다.
- GitHub 배포 ZIP에는 BepInEx 바이너리, 편집 PNG 4개, 번역표, 배치/PowerShell 스크립트, 사용설명서, 외부 라이선스 및 UnityDoorstop 4.6.0 소스가 포함된다. 게임 원본·Windows 글꼴·로컬 조사·백업은 포함하지 않는다.

README를 배포용 소개·설치 매뉴얼로 교체하고 기존 내용을 [개발자 안내](developer-guide.md)에 보존했다. 0.1.4는 설치·배포 방식 개선이며 번역 범위와 아래 게임 화면 검수 한계는 0.1.3과 같다.

## 이전 검증: 0.1.3 — 진행 안내 이미지 번역

2026-11-04, 사용자가 확인한 문 메모를 출발점으로 Texture2D 705개를 목록화하고 메모·지도·포스터·튜토리얼·RGB 계열 후보 이미지를 확인했다. 다음 4개 이미지를 한국어로 편집했다. 자세한 위치·범위·도구·프롬프트는 [이미지 제작 기록](image-texts.md)에 있다.

- `PaperNote`: **2층에서 / 문이 열린 방으로 / 가세요**.
- `CHESA MOODS1`: **E 키: 상호작용**.
- `PUSHHER`: **E 키: 밀기**.
- `CALMHER`: **E 키: 진정시키기**, **체사**, **흐흑…**.

원본 `.assets`는 수정하지 않는다. 명시한 텍스처 이름·크기·재질·속성이 일치하는 슬롯 또는 전체 사각형 튜토리얼 스프라이트만 실행 중 교체한다. 다른 언어로 바꾸거나 패치를 비활성화하면 원래 참조를 복원한다. 원본 텍스처 객체는 그대로 유지한다. 이미지 오류가 생기면 이미지 기능을 중단하고 기존 대사 번역은 계속 동작한다. 대상 `sharedassets2.assets`와 `sharedassets3.assets`의 SHA-256도 호환성 검사에 추가했다. 설치 허용 목록에는 지정된 PNG 4개와 `textures.tsv`만 추가했으며 모두 백업·제거 저널에 포함한다.

직접 확인한 결과:

- 튜토리얼 편집 PNG 3개의 한국어 철자와 레이아웃을 직접 확인했다. 원본 Sprite는 1920×1080 전체 사각형, border 0, pixelsPerUnit 100이었다.

- 최종 0.1.3 설치 → 제거 → 원본 230개 SHA-256 검사 → 재설치 완료. 변경·누락된 원본 0개, 관리 파일 29개. 번역 PNG 4개가 제거되는 것도 확인했다. 근거: `local/verification/image-removal-0.1.3.json`.

- 생성형 편집은 텍스트 밖에도 미세한 변화를 만들 수 있다. 메모와 튜토리얼 원본을 픽셀 단위로 보존했다고 주장하지 않는다.

## 이전 검증: 0.1.2 — 캐릭터·아이템 이름 보완

2026-11-04, 캐릭터 이름과 물건 이름이 영어로 남는다는 제보를 조사했다. 기존 493개는 CSV에서 영어가 있는 키의 수이며, 게임 전체 문자열을 포괄하는 수가 아니었다. 화면 표시 경로를 추가로 확인했다.

- 대사의 화자 이름은 `DialogueLine.speakerName`에서 TMP 텍스트로 직접 전달되어 CSV 번역을 거치지 않는다.
- `ObjectGrabber.TryGrabObject()`는 집어 든 Collider의 `UnityEngine.Object.name`을 `objectNameText.text`에 바로 넣는다. 공책·지갑·펜 등은 이 경로로 표시된다.
- `sharedassets3.assets`의 `ItemData` 7개에는 별도의 `itemName`이 있다. 실제 이름 6개(Beads, Boltcutter, Clinic Key, Gray Key, Violet Key, Crowbar)를 추가했다. `Object6`의 `obj6`는 용도가 확인되지 않은 임시 이름이므로 임의 명칭을 붙이지 않았다.
- 22개 직렬화 파일을 읽기 전용으로 조사했다. 이 빌드의 잡기 레이어 마스크 34816에 해당하는 물리 오브젝트의 표시 이름 7종(복제 번호 포함)은 모두 번역표에 포함되었다. 조사 자료는 `local/survey-extra/`에만 저장한다.

`translations/ui.json`을 11개에서 133개로 확대했다. 제이콥·체사, 공책·지갑·펜·구슬·열쇠·볼트 커터·쇠지렛대, 챕터 선택과 엔딩, 일부 상호작용·미니게임·제작진 역할 문구가 포함된다. 실제 제작진 이름과 서비스명은 유지했다. 기존 CSV 번역과 공백 정규화 별칭을 합친 정확한 UI 일치는 636개다.

새 `DisplayText` 경로가 TMP `text` 설정 직전에 번역하므로 주기적인 화면 검사만 기다리지 않는다. 원본 게임 오브젝트 이름, 아이템 ID, 대사 데이터와 세이브는 바꾸지 않고 표시 문자열만 치환한다. `<color>` 등 바깥 서식 태그, `(Clone)`·숫자 복제 접미사, 점수·백분율 수치를 유지한다. 모르는 문구에 부분 문자열 치환을 하지 않는다. 인스펙터에 미리 저장된 UI에는 기존 주기 검사도 계속 적용한다.

직접 확인한 결과:

- 실제 대사 화자 표시 **제이콥**, 물건을 든 상태의 **공책** 표시 확인. 해당 장면까지의 긴 이동과 아이템 잡기는 사용자가 조작했고, 도구로 화면을 확인했다.
- 챕터 목록의 1일 차·2일 차·2일 차 (깨어남)·3일 차·엔딩, 꿈, 챕터 불러오기·불러오기 표시 확인.
- 새 이름과 기존 대사에 한글 폰트 및 기존 외곽선 유지. 611자 글리프 생성에서 누락 없음.
- C# 표시 변환 검사 16개, Python 설치·데이터 검사 테스트 10개 통과. 리치 텍스트, 공백/줄바꿈, 복제 접미사, 동적 수치, 미등록 문구 보존, 충돌·자리표시자 거부를 검사했다.
- 검사에서 의미 있는 ItemData 이름 6개와 잡을 수 있는 물체 표시 이름 7종의 포함을 확인했다. 모든 아이템을 실제 플레이로 집어 본 것은 아니다.
- 이전 설치 파일은 `local/backups/20261103T160530905524Z/`에 백업한 뒤 업데이트했다. 프로세스가 종료됐음을 확인하고 설치했으며 당시 0.1.2 실행을 검증했다. 검증 로그는 `local/verification/names-items-0.1.2.log`에 있다.

시작 경고와 애니메이션 중 챕터 제목에서 overflow 로그가 추가로 있었다. 챕터 제목은 최종 화면에서 읽을 수 있었으나 시작 경고의 전체 표시와 다른 해상도는 추가 검증 대상이다. 133개 추가 UI 전체를 화면으로 확인한 것은 아니다.

## 이전 검증: 0.1.1 — 자막 외곽선

2026-11-04 후속 검증에서 사용자가 제보한 자막 외곽선 누락을 수정해 실제 설치본에 적용했다. 컴퓨터 사용 중지 상태도 해소되어 게임을 다시 실행했다. 첫 꿈 장면의 흰 배경에서 실제 대사 **우, 우리 아는 사이야?**가 외곽선을 가진 한글로 읽히는 것을 확인했다. 해당 줄은 한 줄로 표시되며 잘림이 없었다. 긴 이동 구간은 사용자가 직접 조작했고, 도착 후 화면을 도구로 확인했다. 모든 대사·분기 검수를 의미하지 않는다.

이전 코드의 `component.fontSharedMaterial = koreanFont.material`이 게임의 자막 재질을 기본 한글 재질로 대체해 외곽선·그림자 설정을 잃게 했다. 수정본은 각 원본 재질에 대응하는 별도 한글 재질을 만들고 `TMP_MaterialManager.CopyMaterialPresetProperties`로 외곽선, 그림자, 글자 색, 셰이더와 키워드를 복사한다. 한글 아틀라스와 SDF 배율은 유지한다. 원본 공유 재질은 수정하지 않으며 다른 언어로 돌아갈 때 원본 재질을 복원한다. 외곽선 여백도 다시 계산한다.

원본 `CuteDino Material`의 외곽선 두께는 약 0.295였다. 실제 게임 로그에서 `outline=0.295 -> 0.295; Korean atlas=True`를 확인했다. 566자 사전 생성은 `complete=True`였으며 글리프 누락은 없었다. 검증 로그는 `local/verification/outline-0.1.1.log`, 원본 재질 조사 결과는 `original-materials.json`에 보관한다. 컴파일·번역 토큰 검사는 통과했다.

실제 설치본에서 0.1.1 적용 → 제거 → 원본 230개 SHA-256 검사 → 재설치 → 게임 실행을 수행했다. 변경·누락된 원본은 0개였고, 제거 단계에서 로더와 설치 목록이 사라진 것을 확인했다. 제거 상태로 원본 게임을 실행하는 시험은 별도로 수행하지 않았다. 근거는 `local/verification/removal.json`과 `final-state.json`이다.

첫 꿈 장면의 밝은 배경에서 인물·이동·대사가 진행되고 이후 실내 장면으로 전환되는 것을 확인했다. 따라서 이전에 흰 화면만 보고 플레이 진행을 확인하지 못했던 제한은 해소했다. 이전 로그의 메뉴 관리자 예외가 원본에서도 발생하는지는 여전히 별도 확인 대상이다.

## 선택한 패치 방식과 이유

BepInEx 5.4.23.6 Mono x64와 직접 작성한 C# 플러그인을 사용한다. `GetText`의 결과를 한국어로 바꾸되 **원래 English 슬롯에서만** 동작한다. 언어의 저장 번호를 바꾸지 않으며 음성 언어를 변경하지 않는다. 언어 메뉴의 English 표시는 한국어로 바꾼다(초기 시험본은 한국어 (패치)). 나머지 언어는 원래 게임 기능을 사용한다. 원본 `.assets`와 게임 DLL은 수정하지 않는다. 별도 MCP 서버는 필요하지 않았다.

Windows에 설치된 `Fonts/malgun.ttf`를 게임 내 TMP의 파일 경로 생성 함수로 읽어 동적 폰트를 만든다. 시스템 폰트를 복사하거나 배포하지 않는다. 첫 시험에서 OS 폰트 이름을 통한 Unity Font 생성은 TMP 폰트 데이터가 없어 실패했으며, 게임 DLL에서 확인한 내부 파일 경로 생성 함수로 해결했다. 이 내부 API 때문에 TMP DLL 해시도 호환성 검사 대상이다.

번역 자료는 원문 키의 SHA-256과 직접 작성한 한국어만 저장한다. 키 기반 번역 외에 CSV 영어 문구와 짧은 UI 문구의 정확한 일치 치환을 사용한다. 같은 영어에 서로 다른 번역이 있으면 일반 UI 치환은 제외하고 키 기반 대사 번역을 유지한다. 원본 CSV와 게임 DLL은 커밋하지 않는다.

## 번역 확대

첫 메뉴 시험 성공 후 영어가 있는 고유 키 493개 전체를 번역했다. 메뉴·설정·대사·목표·튜토리얼·안내 문구가 포함된다. `translations/ko.json`에는 원문 키의 SHA-256과 한국어만 저장한다. 원문 영어와 필요한 Filipino 문맥을 참고해 작성한 초안이며, 사람의 전체 문맥 교정은 남아 있다. `translations/glossary.json`에 인명과 용어 기준을 기록했다.

`translations/ui.json`에는 Continue, 품질 단계, 켜짐/꺼짐, Steam 리뷰 안내 등 CSV 외의 추가 UI 문구 11개가 있다. 영어가 비어 있는 고유 키 63개는 번역하지 않았다. 이미지에 그려진 글자, 음성, 모든 동적 문자열을 포괄한다고 주장하지 않는다.

게임의 CSV 파서는 ASCII 큰따옴표를 제거하므로 원본 키와 제거 후 키를 함께 지원한다. 결과는 키 별칭 494개, 정확한 영어 UI 일치 504개이며 서로 다른 번역이 충돌하는 UI 항목은 0개였다. 변수·서식 태그·대괄호 조작 키 27개를 원문과 비교해 보존을 확인했다.

French 선택 중 한국어 옵션에 네모 글자가 나타나고 한국어 전환 직후 폰트 갱신이 늦는 현상을 발견했다. 소스에서는 TMP 텍스트/폰트 설정 시 한글 폰트를 먼저 준비하고 기존 폰트에 fallback을 연결하도록 수정했다. 좁은 UI는 기존 크기의 65%까지 자동 축소하며 다른 언어에서는 기존 레이아웃을 복원한다. 로딩 문구를 짧게 바꾸고 언어 선택 표시를 한국어로 줄였다.

당시 폰트·레이아웃 수정본은 빌드와 패키징까지만 완료했다. 사용자가 실수로 Esc를 눌러 컴퓨터 사용이 중지되었고, 재개 승인 뒤에도 도구가 중지 상태를 반환했다. 이후 0.1.1에서 이 수정과 외곽선 수정을 함께 적용해 실행했다. 최신 결과는 이 문서 첫 절을 따른다.

장면 진입 시 Player.log에 `SlimUI.ModernMenu.UIMenuManager.Start`의 NullReferenceException이 있었다. 흰 화면과의 관련성, 원래 게임에서도 발생하는지, 패치 영향인지는 확인하지 못했다. 이전 설치본에는 CuteDino의 한글 글리프 경고도 있었으므로 최신 fallback 수정 후 재검증이 필요하다. 이를 해결됐다고 간주하지 않는다.

1. 꿈 장면의 3D 조작 안내에서 마우스: 둘러보기가 어색하게 두 줄로 나뉘며 해당 안내와 WASD: 이동의 overflow 로그가 남는다. 3D 텍스트의 폭·글자 크기를 별도로 조정한다. UI 자동 축소만으로 해결됐다고 간주하지 않는다.
2. 튜토리얼 이미지 3개의 실제 화면과 다른 언어 복원을 검증한다. 추가 이미지의 우선순위는 [이미지 조사 기록](image-texts.md)을 따른다. `obj6`의 용도, 미검토 UI 후보와 모든 아이템의 실제 획득 화면도 확인한다.
3. 긴 대사의 타이핑·줄바꿈·다른 해상도를 추가 검증한다. 0.1.3에서 확인한 문 메모와 설정의 French 왕복 전환 결과를 모든 UI의 검증으로 확대 해석하지 않는다. 시작 경고의 문구 잘림 여부도 확인한다.
4. 모든 챕터·분기·엔딩을 플레이하며 번역 문맥, 발화자, 존댓말과 용어를 교정한다.
5. 필요하면 제거 상태의 원본 게임 실행과 비교해 메뉴 관리자 예외를 조사한다. 제거와 원본 파일 복원 검사는 이미 통과했다.
6. 게임 업데이트가 나오면 원본 해시·텍스트·TMP 내부 API를 재조사한다. 현재 빌드 외의 호환성은 미확인이다.

## 출처

- [BepInEx 공식 릴리스](https://github.com/BepInEx/BepInEx/releases): 로더와 의존성.
- [UnityPy](https://github.com/K0lb3/UnityPy): 읽기 전용 에셋 조사.
- [TextMeshPro TMP_FontAsset API](https://docs.unity3d.com/Packages/com.unity.textmeshpro@3.0/api/TMPro.TMP_FontAsset.html): 동적 글꼴 생성 참고. 실제 게임 DLL의 API와 실행 결과를 우선한다.
- [TMP_MaterialManager API](https://docs.unity3d.com/ja/Packages/com.unity.textmeshpro%403.0/api/TMPro.TMP_MaterialManager.html): 대상 폰트 아틀라스 속성을 유지하며 원본 재질 설정을 복사하는 API. 로컬 Unity 패키지 소스와 실제 게임 빌드로도 확인했다.
